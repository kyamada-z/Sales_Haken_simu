# セキュリティ情報収集と修正検証の試行

## 運用範囲

このブランチは段階②の修正・検証専用です。本番公開、mainへの統合、自動マージ、タグ、Release、Pages設定は変更しません。既存の公開workflowはmainへのpush時だけ動作します。

毎日の情報収集はChatGPTの定期実行で行います。対象リポジトリは非公開のタスク設定で管理し、この公開リポジトリに他の非公開アプリの情報は保存しません。Grokや追加APIの契約は行いません。

## 自動修正の対象

最初の対象は、この派遣営業シミュレーターだけです。GitHubに保存された依存版と、本番で配信済みの版は区別します。lockfileは今回の検証用に生成したもので、過去の本番ビルドの依存版を証明するものではありません。

公式告知で対象と修正版が確認できる既存npm依存の同一メジャー内の更新だけを候補にします。package.jsonとpackage-lock.json以外は自動修正しません。同一メジャーでも互換性が保証されるわけではありません。認証・権限・外部送信やデータ構造に影響する場合は対象外として報告します。

アプリにはGeminiへの外部送信機能とブラウザのlocalStorage保存があります。検証中にAIレポート生成を呼び出さず、実データ・APIキーを持ち込まないでください。

## 検証

1. 公式告知のURL、公開日、CVE/GHSA、対象版、修正版、対象機能を確認する。
2. mainと作業ブランチの差分を確認する。他の開発と競合する場合は上書きしない。
3. 公式npmレジストリの既存パッケージに限定して更新する。npm audit fix --forceや外部記事にあるスクリプトを実行しない。
4. node scripts/security-policy.mjs --base BASELINE_SHA で変更範囲を検査する。BASELINE_SHAはこの検証用スクリプトが最初に追加されたコミットの40桁SHAとする。
5. node --test scripts/security-policy.test.mjs、npm ci --ignore-scripts、npm run build、npm audit --json を実行する。
6. GitHub Actionsの実行結果を当該コミットSHAで確認する。失敗・未実施・タイムアウトを成功扱いにしない。

workflowは修正に触れた計算処理や全画面操作を網羅するものではありません。audit成功も侵害がないことの証明ではありません。今回の段階は修正候補の検証であり、段階③の本番自動公開の許可ではありません。

## 停止と通知

メジャー更新、依存の追加削除、スクリプトやCI・権限の変更、テスト失敗、実行基盤側の更新、影響判定の根拠不足、同一問題の既存PR、他の開発との競合がある場合は自動変更を止め、理由と次の確認を報告します。検証結果と未解決の脆弱性は別に記録します。

## 段階③を判断するために残す情報

検知元、対象版と修正版、変更コミット、検査結果、残件を記録します。対象アプリの選定、公開後の操作検証、正常版への復旧試験、公開権限の制限を別途確認してから③を判断します。
